## 1. 为什么收尾

这一代实现是在 WebView 里长出来的：播放、超分、下载管理共用一套前端状态，改一处会牵动三处。继续在原地加功能，成本已经高于重写。

所以拆成两件事：

- **本仓库**：把已经能用的部分修到「说得清、不闪退、不骗人」，冻结功能，不再追新。
- **新仓库**：从底层到 UI 完全重构，与上游源仓库分家，**不继承本仓库的任何设计**。设计文档不随本仓库保留。

分家的具体含义：**不再 merge 上游**，不再沿用上游的界面结构；上游的更新如果有价值，人工挑选后重写，而不是合并。本仓库只接受收尾范围内的修复。

## 3. 本仓库冻结、不做

以下在本仓库一律不做，也不作为新仓库的待办清单——新仓库重新设计，不是把这些补上就行：

| 项 | 为什么不做 |
| --- | --- |
| 底部四入口导航（首页/分类/下载/我的） | 需要重排整个页面结构，属于重构而非收尾 |
| 完整分类模型（热门时间窗、分辨率体系、题材全集、排除标签） | 要同时改查询层与 UI，牵动登录态/匿名态两套参数 |
| 统一状态层（任务、区间水位、存储性质单一来源） | 现存记录格式要迁移，属于新仓库的地基 |
| libmpv 双内核 / 原生超分移植 | 见 `PLAYER_ARCHITECTURE.md`：单内核已够，移植属于新仓库 |
| 边下边看接入原生内核（自定义 `DataSource`） | 要先把统一字节缓存层做出来，否则是无源之水 |
| 删除 `assets/sr/` 旧 WebGL 链路 | 它是当前唯一的回退路径，删了就没有兜底 |

## 4. 与新仓库的关系

- 新仓库**不继承**本仓库的任何设计：不改写、不移植类结构、不复用布局与资源命名、不沿用旧的状态字段。
- 新仓库的设计文档不在本仓库内，也不由本仓库维护；本仓库不再保留任何设计方案、路线图或阶段计划。
- 本文与 `PLAYER_ARCHITECTURE.md`、`NATIVE_SUPER_RESOLUTION.md` 都是本仓库的过程记录，**不迁移**。它们留着是为了解释「为什么当初这么决定」，不是给新仓库当前置阅读。

---

## 5. 本仓库还接受什么

只接受这四类：

1. 构建失败 / CI 失败。
2. 崩溃、黑屏、无法播放。
3. 事实性错误（文档写的和代码做的不一致）。
4. 安全问题（凭据泄露、越权访问）。

新功能、界面调整、性能优化一律拒绝。
