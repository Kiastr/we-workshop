# 本仓库收尾边界（REPO_SCOPE）

记录日期：2026-11-16  
适用版本：v0.6.3（收尾版，功能冻结）

---

## 1. 为什么收尾

这一代实现是在 WebView 里长出来的：播放、超分、下载管理共用一套前端状态，改一处会牵动三处。继续在原地加功能，成本已经高于重写。

所以拆成两件事：

- **本仓库**：把已经能用的部分修到「说得清、不闪退、不骗人」，冻结功能，不再追新。
- **新仓库**：按完整设计重新组织（原生播放器、统一状态层、完整分类），与上游源仓库分家。

分家的具体含义：**不再 merge 上游**，不再沿用上游的界面结构；上游的更新如果有价值，人工挑选后重写，而不是合并。本仓库只接受收尾范围内的修复。

## 3. 本仓库明确不做

以下都留给新仓库，本仓库不会做「半成品」：

| 项 | 为什么不做 |
| --- | --- |
| 底部三 tab 导航（工坊/下载/设置） | 需要重排整个页面结构，属于重构而非收尾 |
| 完整分类模型（热门时间窗、分辨率体系、题材全集、排除标签、`FilterSpec`） | 要同时改查询层与 UI，牵动登录态/匿名态两套参数 |
| 统一状态层（`DownloadRepository` + Room + DataStore） | 现存记录格式要迁移，属于新仓库的地基 |
| libmpv 双内核 / 原生超分移植 | 见 `PLAYER_ARCHITECTURE.md`：单内核已够，移植是下一阶段的事 |
| 边下边看接入原生内核（自定义 `DataSource`） | 要先把统一字节缓存层做出来，否则是无源之水 |
| 删除 `assets/sr/` 旧 WebGL 链路 | 它是当前唯一的回退路径，删了就没有兜底 |

## 5. 新仓库的起点

按依赖顺序，新仓库第一件事不是画界面：

1. **统一字节缓存层**：一份数据同时喂下载与播放，区间水位可查询、可等待。
2. **`DownloadRepository` + Room**：任务状态、断点、完成记录单一来源。
3. **`FilterSpec`**：同组 OR、跨组 AND、`excludedtags[]`，登录态与匿名态各一个适配器。
4. **导航骨架**：工坊 / 下载 / 设置三入口。
5. **播放器**：沿用本仓库的 `PlayerActivity` 骨架（已解耦控件层与 `Player` 接口），接第 1 步的 `DataSource`。
6. **超分**：按 `NATIVE_SUPER_RESOLUTION.md` 移植 `GlEffect`，或按 ADR-001 的改判条件引入 libmpv。

本仓库的 `docs/PLAYER_ARCHITECTURE.md`、`docs/NATIVE_SUPER_RESOLUTION.md`、`docs/VIDEO_CLIENT_REDESIGN.md` 三份文档是交接材料，可直接带过去。

## 6. 本仓库还接受什么

只接受这四类：

1. 构建失败 / CI 失败。
2. 崩溃、黑屏、无法播放。
3. 事实性错误（文档写的和代码做的不一致）。
4. 安全问题（凭据泄露、越权访问）。

新功能、界面调整、性能优化一律拒绝，转新仓库。
