# WE Workshop 视频客户端重构方案

状态：已确认产品方向，待分阶段实施  
记录日期：2026-11-15

## 1. 产品定位

WE Workshop 是一个类似 B 站的 Wallpaper Engine 创意工坊视频客户端：用户浏览内容、点击视频、直接播放；下载、缓存、网络和文件管理是支撑这条体验的底层能力。

它不是以任务列表为中心的下载管理器，也不是需要用户手工选择文件的本地播放器。

核心原则：

1. 内容卡片是入口，播放详情页是核心场景。
2. 点击卡片即进入播放，不经过“详情弹窗 → 下载 → 播放器 → 选文件”。
3. 下载器能力隐藏在起播、拖动、缓存和保存背后。
4. 原画 4K60 播放性能是基线，任何增强功能不得破坏它。

## 2. 核心用户流程

```text
点击视频卡片
    │
    ├─ 已下载 ───────→ 打开播放页，立即本地播放
    │
    ├─ 已有完整缓存 ─→ 打开播放页，立即缓存播放
    │
    └─ 尚未缓存 ─────→ 打开播放页
                         ├─ 立即显示封面、标题与可用操作
                         ├─ 后台建立播放缓存
                         ├─ 达到可播放条件后自动起播
                         └─ 播放过程中继续缓存

播放页点击「下载」
    └─ 当前缓存任务转为正式下载，复用全部已有数据，不重新开始
```

### 2.1 播放缓存与正式下载

| 类型 | 产生方式 | 用途 | 清理策略 |
| --- | --- | --- | --- |
| 播放缓存 | 点击播放自动产生 | 起播、拖动、再次观看 | 按容量自动淘汰，可手动清理 |
| 正式下载 | 用户主动点击下载 | 长期保存、导出、离线观看 | 永不自动删除 |

两者必须共享同一个字节缓存和同一个传输任务。播放中点击下载只改变持久化属性，不重启任务、不新建第二份文件、不中断播放。

默认规则：

- Wi-Fi 下允许自动起播；移动网络默认先询问，设置中可改。
- 仅用于播放的任务在退出播放页后停止继续拉取整部视频，但保留已有分片。
- 正式下载在退出播放页后继续执行。
- 当前播放、正式下载和已锁定的内容不得被缓存淘汰。
- 清理播放缓存不得删除正式下载。

### 2.2 状态模型

不能用“未下载 / 下载中 / 已下载”一个枚举同时描述所有状态。每个工坊条目至少有四个相互独立的状态轴：

- `PlaybackSession`：未播放、准备中、可播放、播放中、暂停、失败。
- `TransferState`：空闲、传输中、暂停、失败、完成。
- `ByteAvailability`：已缓存区间、连续可播水位、索引是否可用。
- `StorageState`：无本地数据、临时缓存、完整缓存、正式下载。

同一个条目只能有一个写入任务。播放、拖动、正式下载和边下边看都读取同一份区间水位。

## 3. 信息架构

底部保留四个一级入口：

| 入口 | 职责 |
| --- | --- |
| 首页 | 搜索、热门、最新、订阅最多、最高评分、视频内容流 |
| 分类 | 完整 Wallpaper Engine 分类、题材、分辨率、特性与排除标签 |
| 下载 | 下载中、已下载、播放缓存与存储管理 |
| 我的 | 观看历史、Steam 登录、网络加速、播放、缓存与诊断设置 |

首页默认聚焦可播放的视频。分类页覆盖完整工坊；Scene、Web、Application、Preset、Asset 等非视频内容进入资源详情页，不打开黑屏播放器。

### 3.1 首页卡片

- 16:9 封面，统一网格与间距。
- 显示时长、真实分辨率、帧率和内容类型。
- 标题最多两行，下方显示作者与可用的工坊统计。
- 整张卡片点击即播；更多菜单提供直接下载、查看详情、复制工坊链接。
- 已缓存、已下载只以轻量图标表示。
- 返回首页必须恢复筛选条件、列表数据和滚动位置。

### 3.2 排序与时间窗口

热门排序提供：今日、本周、本月、近三月、近半年、年度、全部。

同时保留最新发布、最近更新、订阅最多、最高评分和搜索相关度。时间窗口只与适用的排序绑定，不显示为无关筛选条件。

### 3.3 完整分类

筛选分为：内容形式、工坊类别、题材、宽屏/超宽屏/双屏/三屏/竖屏分辨率、功能特性、年龄分级和排除标签。

- 同组多选为 OR，跨组为 AND。
- 支持包含与排除标签。
- UI 统一产出 `FilterSpec`；匿名网页与登录态 `QueryFiles` 各自只做参数适配。
- 标签目录采用“远端同步 + 本地版本化兜底”，避免硬编码快照随着工坊变化再次变成不完整分类。

## 4. 播放详情页

播放与详情是同一个页面，不再使用 WebView 弹窗。

```text
┌──────────────────────────────┐
│        原生视频播放区         │
│   封面 → 缓冲 → 自动播放      │
│   返回 / 小窗 / 全屏          │
├──────────────────────────────┤
│ 视频标题                      │
│ 作者 · 分辨率 · 帧率 · 大小    │
│ 下载 / 分享 / 更多            │
│ 缓存进度 / 下载状态           │
├──────────────────────────────┤
│ 简介、标签、工坊信息           │
├──────────────────────────────┤
│ 相关推荐                      │
└──────────────────────────────┘
```

行为要求：

- 页面先出现封面和标题，不能等视频可播后才显示界面。
- 加载提示区分连接、读取视频索引、缓冲和准备解码。
- 等待超过正常时间后展示速度、进度和可操作的失败原因。
- 下载按钮直接呈现任务状态，切换正式下载不影响播放。
- 相关推荐基于共同题材、类型等可解释规则，不伪装成云端个性化算法。
- 不虚构弹幕、评论、关注或多个云端清晰度等不存在的数据能力。

## 5. 原生播放器交互

- 使用 Material Symbols Rounded 图标，移除“返回列表”“开启全屏”等文字按钮。
- 顶部：返回、标题、小窗、更多。
- 中央：播放/暂停。
- 底部：进度条、时间、倍速、画质、画面比例、锁定、全屏。
- 控件自动隐藏，触控目标至少 48dp。
- 单击显隐控件；双击左右快退/快进；横向拖动定位；左侧亮度、右侧音量；长按临时倍速；双指调整画面比例。
- 横屏视频进入真正的 `SENSOR_LANDSCAPE` 与沉浸模式，竖屏视频不强制旋转。
- 旋转不得重建播放会话或从头播放；退出全屏回到原播放详情页。

画质面板显示原始规格、呈现模式、当前内核和实际运行状态。工坊只有一个原始文件时，不提供虚假的 720p/1080p 云端清晰度切换。

当前实现与上表的差距（截至 v0.6.2）：已落地返回、标题、更多、中央播放暂停、进度条、时间、全屏、单击显隐、双击左右 ±10s、左亮度右音量、横向拖动带时间气泡；**待补**倍速、画质面板、画面比例、方向锁定语义、小窗、双指缩放。逐项优先级与验收见 `docs/PLAYER_ARCHITECTURE.md` 第 7、8 节。

## 6. 下载与起播的技术要求

播放器和正式下载共用统一字节缓存层，不再分别维护文件。

- MP4 索引在头部时，满足最小可播数据量后起播。
- 索引在尾部时优先获取尾部索引，再调度头部媒体数据。
- 拖动到未缓存区域时，提高目标位置附近区间的优先级，随后恢复原任务。
- CDN 或文件结构不支持时，明确进入完整下载等待，不伪报可播。
- 不转码、不降低源清晰度，保留工坊原始视频字节。

## 7. 性能与超分边界

默认原画链路必须是原生硬件解码直出，不允许 WebView、JavaScript 逐帧回调、位图拷贝或固定 30 FPS 控制器进入该链路。

超分**不是第二个播放内核**，而是同一个 Media3 内核上的可选 effect 链：原画时不挂任何 `GlEffect`（解码器直出 SurfaceView，零额外 GPU 开销），只有用户选增强档才挂上 GL 处理。

- 低分辨率源才执行真正的放大。
- 2K/4K 源默认原画，可选择锐化或恢复，不强行生成 5K/8K。
- 全局默认、单视频覆盖和运行时自动降档分开保存。
- 增强链必须通过实际渲染 pass 和输出尺寸验证，不能只凭"注入成功"显示已生效。
- 增强不满足帧预算时自动降档或回退原画，不能牺牲正常播放。
- 帧数据全程在 GPU 上，不经过 Bitmap、ByteBuffer 或 JavaScript。

详细技术路线见 `docs/NATIVE_SUPER_RESOLUTION.md`。

## 8. 实施顺序

| 阶段 | 交付重点 |
| --- | --- |
| 1. 播放主链路 | 新播放详情页、已下载/已缓存内容立即播放、原生全屏和图标控制器 |
| 2. 缓存与下载统一 | 远程内容自动缓存起播、缓存转正式下载、统一区间水位与任务 |
| 3. 视频化首页 | 新卡片流、完整热门时间分类、返回状态恢复、相关推荐 |
| 4. 完整分类 | 类型、题材、分辨率、特性、年龄分级、排除标签与查询语义 |
| 5. 性能与超分 | 4K60 原画基线、GlEffect 增强链、默认引擎与能力检测 |
| 6. 清理与文档 | 移除旧弹窗播放器和 JS 超分链路，重写 README 与兼容性说明 |

每阶段独立构建、真机验证和回归，不把整个重构压成一个不可定位的大改动。

## 9. 产品验收标准

1. 点击任意可播放视频卡片只经过一次页面跳转就进入播放页。
2. 已下载视频不需要再次选择文件，直接播放。
3. 播放中点击正式下载不重新开始、不新建重复任务、不中断画面。
4. 返回首页后筛选和滚动位置保持不变。
5. 全屏真实旋转并隐藏系统栏，退出后回到原详情页。
6. 原画播放不经过 WebView 或 JS 帧管线。
7. 4K60 性能以解码器、实际呈现帧率和丢帧数据验收，不以主观“看起来流畅”验收。
8. 超分失败或性能不足时可回退，但原画播放始终可用。
9. 清理缓存不影响正式下载。
10. 新 README 首先解释“浏览 → 点击即播 → 需要时下载”，不再以历史修复记录作为产品说明。
